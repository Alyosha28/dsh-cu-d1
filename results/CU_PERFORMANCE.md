# Computer Use 时延测量与优化

日期：2026-10-31

## 成本分解

在 2508×1671 的 Retina 窗口上逐项测量，重复三次取中位数。

- D1 单次决策，原图输入：879 毫秒
- D1 单次决策，800 宽输入：310 毫秒
- D1 单次决策，1280 宽输入：650 毫秒
- 截图，列表页：350 到 450 毫秒
- 截图，长文章页：760 到 970 毫秒
- 中文 OCR，整窗：480 到 590 毫秒
- 中文 OCR，1280 宽：450 到 460 毫秒
- CUA `getApp` 握手：138 到 330 毫秒
- 指示器 Swift 编译：650 毫秒
- 指示器辅助进程启动：280 毫秒
- `npx tsx` 进程启动：约 900 毫秒
- 热态滚动：58 到 68 毫秒
- 指示器活动事件：0 毫秒

OCR 对输入尺寸不敏感，缩放在 Vision 内部抵消，保持原图。

## 已实施优化

- 决策服务在视觉编码前把超过 800 像素宽的截图等比缩小。归一化包围盒与像素尺寸无关，坐标映射不受影响。`DSH_CU_VISION_WIDTH` 可覆盖该阈值。
- `scripts/cua-session.mts` 提供常驻执行会话，一次启动后复用 CUA 会话、窗口句柄与指示器，命令经标准输入逐行提交并串行执行。
- 决策服务以 `HF_HUB_OFFLINE=1` 与 `TRANSFORMERS_OFFLINE=1` 启动，避免加载阶段访问模型仓库。
- 中文 OCR 使用 `zh-Hans` 与 `en-US` 双语识别。
- 文章读取按连续两帧相同判定到达底部，不再依赖固定屏数。
- 会话提供 `activate` 与 `restore`，记录并恢复用户原来的前台应用。
- 原生接管判定要求目标应用处于前台，其他应用覆盖在目标窗口上的点击不再触发暂停。

800 宽输入的决策在文章列表上连续六次选择 `CLICK`，与 1280 宽一致。

## 边界

- 微信文章页只在应用处于前台时响应坐标点击，后台点击返回成功但页面不跳转。此类界面需要 `activate` 与 `restore` 配合。
- 整窗多卡片布局下 D1 返回 `BLOCKED`，把决策输入裁剪到单张卡片后可稳定选中。裁剪区域决定定位质量。
- 截图时延由官方 CUA 原生捕获决定，接口不提供缩放参数。
